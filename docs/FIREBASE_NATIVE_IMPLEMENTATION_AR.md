# تنفيذ Firebase الأصلي لمتجر APEX

## الحالة الحالية

هذا الفرع يحتوي الآن على طبقة تشغيل Firebase وتكامل أولي للواجهة والخدمات الخلفية، لكنه **لم يُنشر على Firebase ولم تُرحّل بيانات Supabase**. لا تعتبر المتجر جاهزاً للإنتاج قبل تهيئة المشروع وتشغيل اختبارات قبول حقيقية.

## ما تم بناؤه في هذا الفرع

- Firebase Web SDK بإصدار مثبت، مع ملف إعداد محلي متجاهل Git.
- طبقة توافق `firebase/compat.js` تربط واجهة المتجر ولوحة الإدارة بـ Firebase عند وجود إعداد Web صالح، وتُبقي Supabase fallback عند غياب الإعداد.
- Auth بالبريد وكلمة المرور، واستعادة كلمة المرور، وتحديث الملف الشخصي، وتدفق OTP رقمي من 6 أرقام عبر Callable Functions.
- Firestore/Storage rules وفهارس أساسية.
- Cloud Functions:
  - `apexCreateOrder`: إنشاء طلب بقراءة الأسعار من الخادم، وتثبيت الأسعار في تفاصيل الطلب، وidempotency.
  - `apexWalletCheckout`: خصم المحفظة وإنشاء الطلب والقيد المحاسبي في معاملة ذرية.
  - `apexAdminCustomers`: قائمة العملاء وملخص الطلبات للمدير.
  - `apexAiGuard`: تسجيل أحداث أمنية، تحديد معدل، وإرسال تقرير المدير.
  - `apexEmailCampaign`: إرسال الحملات للمشتركين الذين وافقوا على التسويق.
  - `apexStoreAssistant`: مساعد المتجر مع حصر الاستعلام عن الطلب بحساب صاحبه.
  - خدمات مساندة لطلب OTP وإكمال التسجيل، وشحن المحفظة اليدوي ومراجعته، واسترداد الطلب للمحفظة، والدعوات، وقراءة طرق الدفع العامة المنقحة.
- إدارة المنتجات والبنرات والطلبات وطرق الدفع والإعدادات من خلال Firestore عند تفعيل Firebase.
- رفع الصور إلى Cloud Storage، مع شرط Custom Claim للمدير.

## حدود التنفيذ الحالية

- لا توجد إعدادات Web App الفعلية في `firebase/runtime-config.js` حتى الآن.
- لا توجد أسرار Resend أو OpenAI مضبوطة في Firebase Secret Manager.
- لم يتم نشر Cloud Functions أو القواعد إلى مشروع Firebase.
- لم يتم إنشاء مستند المدير ولا منحه Custom Claim.
- لم يتم نسخ المنتجات والبنرات وطرق الدفع والعملاء والطلبات من Supabase إلى Firestore.
- بوابات Tabby وTamara وPayPal وMoyasar غير متصلة في هذا التنفيذ؛ إنشاء الطلب يدعم حالياً طرق الدفع اليدوية ومحفظة APEX فقط.
- OTP والطلبات والمحفظة مكتوبة على Firebase، لكن يلزم اختبار end-to-end على مشروع اختبار فعلي قبل اعتمادها.
- بعض بيانات الدعوات/المكافآت القديمة قد تتطلب استكمال قواعدها التجارية قبل نقلها.

## الإعداد المطلوب

راجع `docs/FIREBASE_DEPLOYMENT_AR.md` لتسجيل Web App، تفعيل Auth/Firestore/Storage، ضبط Secrets، إضافة المدير، ثم النشر بعد الاختبار.

## سياسة الأمان والترحيل

- لا تحذف Supabase ولا تعدّل بياناته أثناء هذه المرحلة.
- لا تُرسل Service Account أو مفاتيح الدفع أو Resend أو OpenAI داخل المحادثة أو GitHub.
- لا يستطيع العميل تعديل السعر النهائي أو رصيد المحفظة أو منح نفسه صلاحية المدير.
- قراءة طرق الدفع العامة تمر عبر callable يعيد الحقول المسموح عرضها فقط؛ المستند الخام مقصور على المدير.
- نقل بيانات الإنتاج يتطلب نسخة احتياطية ومقارنة أعداد/مجاميع وموافقة منفصلة.
- لا دمج إلى `main` ولا نشر إنتاج من هذا الفرع دون موافقة صريحة.

## الاختبارات

GitHub Actions يفحص صياغة JavaScript، ويحمل قواعد Firestore وStorage وCloud Functions عبر Firebase Emulator. نجاح هذه الفحوصات لا يغني عن اختبار تسجيل حساب حقيقي، OTP، إنشاء طلب، خصم المحفظة، مراجعة الشحن، صلاحيات المدير، رفع الصور، البريد، ومساعد المتجر في مشروع Firebase منفصل.
